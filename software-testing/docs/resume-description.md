# 简历项目描述与面试讲述

## 简历版本

**学生请销假系统测试项目｜软件测试**  
技术栈：Playwright、JavaScript、Postman 思维、Vue 3、Spring Boot、MySQL

- 分析学生登录、强制改密、请假/返校/续假、管理审批等业务，运用等价类、边界值、场景法和权限矩阵设计 30+ 条功能、接口与安全测试用例。
- 使用 Playwright 搭建 API + Web UI 自动化测试框架，覆盖认证会话、异常参数、分页边界、路由保护和管理端权限，生成 HTML 报告、失败截图、视频及 Trace。
- 通过未登录访问、学生越权和前后端数据契约测试，发现管理端接口无鉴权、学号规则与初始化数据不一致等 P0/P1 缺陷，推动增加独立管理员会话、接口拦截器和路由守卫，并完成 27 条自动化回归。
- 建立缺陷闭环机制：修复前用预期失败标记保留证据，修复后转为普通回归断言，最终实现 27 条接口/UI/移动端自动化全部通过。

## 面试中的项目介绍（约 1 分钟）

这个项目是一个 Vue 和 Spring Boot 实现的学生请销假系统。我没有只做页面点测，而是先按学生端、管理端和权限边界拆分需求，再用等价类、边界值和场景法建立用例库。自动化部分使用 Playwright，一套框架同时覆盖接口和 UI，主要验证登录会话、首次改密、分页参数、管理端路由与越权访问。

测试中最重要的发现是管理端接口没有身份认证，未登录用户和普通学生都能读取审批数据；另外前端要求 10 位学号，但初始化账号只有 7 位，导致测试账号无法从页面登录。我把问题按 P0/P1 分级，保留了可复现的自动化用例，并给出了后端授权、前端路由守卫和数据规范统一的修复建议。

## 常见追问

**为什么选择 Playwright？**  
它同时支持浏览器 UI 和 APIRequestContext，能复用配置、报告和断言体系；失败时自动保留 Trace、截图与视频，定位成本较低。

**如何避免自动化污染数据库？**  
查询类用例优先；写接口使用非法参数验证权限顺序；必须写入时准备独立测试数据，并在用例后清理。测试环境与生产库严格隔离。

**为什么管理端无鉴权是 P0？**  
它不仅泄露学生审批数据，还可能允许匿名审批和角色修改，直接破坏保密性与完整性，是发布阻断问题。

**UI 和接口测试如何分工？**  
参数组合、状态码和权限边界主要放在接口层；页面控件、前端校验、路由跳转和关键用户路径放在 UI 层，减少重复和脆弱用例。
