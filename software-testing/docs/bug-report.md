# 缺陷报告

测试日期：2026-10-29  
测试环境：Windows、Chromium、Vue 3、Spring Boot 2.7、MySQL

## BUG-001 管理端接口和页面缺少身份认证与角色授权

- 严重程度：P0 / 严重
- 状态：已修复，27 条自动化回归通过
- 影响范围：全部 `/api/admin/**` 接口及 `/admin` 页面

复现步骤：

1. 清除会话或使用全新浏览器上下文。
2. 请求 `GET /api/admin/approvals`。
3. 请求 `GET /api/admin/statistics`，或直接访问 `/admin`。

实际结果：未登录请求返回业务码 200 和审批/统计数据；页面直接展示管理功能。学生登录产生的会话也能调用管理接口。

预期结果：未登录返回 401；普通学生返回 403；只有具备明确管理员身份及对应角色权限的账号才能读取或修改管理数据。

定位：`AdminApprovalController` 所有方法均无会话校验或授权注解，前端路由也没有导航守卫。

修复建议：引入 Spring Security；区分 STUDENT/ADMIN 身份；后端按角色执行授权，前端导航守卫只作为体验补充；审批写操作增加操作人审计。修复后执行 QA-SEC-001~004、QA-UI-005 回归。

修复结果：新增管理员账户与独立会话、后端管理接口拦截器、学生/管理员权限隔离、管理端登录页和路由守卫；补充 QA-SEC-005/006 防止学生接口参数绕过。

## BUG-002 前端学号规则与初始化测试数据不一致

- 严重程度：P1 / 高
- 状态：已修复，回归通过
- 影响范围：首次登录

复现步骤：

1. 使用旧版 `data.sql` 初始化数据库，获得账号 `2024001/123456`。
2. 打开学生登录页并输入该账号。
3. 点击登录。

实际结果：前端正则 `^\d{10}$` 拦截 7 位初始化账号，提示“请输入10位数字学号”，请求无法发送。

预期结果：初始化账号应满足前端规则，或前端规则应与实际学号数据规范保持一致。

定位：`LoginForm.vue` 要求 10 位；`data.sql` 提供 7 位账号。

修复建议：由需求明确学号长度，在前后端与初始化数据中统一；增加契约测试和测试数据校验。

修复结果：初始化学号统一为 `2024000001`、`2024000002`，与前端 10 位规则一致。

## BUG-003 业务错误仍返回 HTTP 200

- 严重程度：P2 / 中
- 状态：待确认
- 影响范围：登录、未授权和参数错误接口

复现步骤：错误密码调用 `POST /api/student/login`，观察 HTTP 状态和响应体。

实际结果：HTTP 状态为 200，响应体业务码为 401。未登录和参数错误也采用相同模式。

预期结果：HTTP 状态与错误语义一致，例如参数错误 400、未认证 401、无权限 403；响应体保留统一错误结构。

风险：网关、监控、缓存和通用客户端会把失败请求统计为成功，影响告警与可观测性。

修复建议：Controller 使用 `ResponseEntity` 或全局异常处理器统一映射 HTTP 状态，同时保持兼容的 JSON 错误结构。

## BUG-004 CORS 对任意来源开放并允许携带凭据

- 严重程度：P1 / 高
- 状态：已修复，回归通过
- 影响范围：所有后端接口

实际结果：配置同时使用 `addAllowedOriginPattern("*")` 和 `setAllowCredentials(true)`。

风险：任意站点可能发起携带用户会话的跨域请求；与管理端未鉴权问题叠加时风险进一步放大。

修复建议：使用环境变量维护明确的前端域名白名单；生产环境禁止通配来源；补充恶意 Origin 预检测试。

修复结果：后端默认仅允许 `127.0.0.1:5173` 和 `localhost:5173`，可通过 `app.cors.allowed-origins` 配置；不受信任 Origin 预检已返回 403 且不再携带允许来源/凭据响应头。
