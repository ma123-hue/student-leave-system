# 学生请销假系统测试计划

## 1. 测试目标

验证学生请销假系统核心业务可用性、前后端接口一致性、异常处理和权限隔离能力；通过自动化回归降低登录、审批和角色切换功能改动后的回归成本。

## 2. 测试范围

范围内：

- 学生端：登录、首次改密、会话、请假申请、撤销、返校、续假和记录查询。
- 管理端：待审批列表、搜索筛选、审批/驳回、角色切换、统计和历史记录。
- 接口：参数校验、状态码、响应结构、分页边界、未登录访问和越权访问。
- Web：路由、表单校验、错误提示、核心导航与桌面 Chromium 兼容性。

暂不包含：

- 短信、统一身份认证等未接入的第三方系统。
- 大规模性能压测、弱网移动端专项和生产数据迁移。
- MySQL 故障恢复及多实例高可用测试。

## 3. 测试方法

| 方法 | 应用场景 |
| --- | --- |
| 等价类 | 正确/错误学号、密码、角色和审批类型 |
| 边界值 | 学号长度、密码 6-32 位、分页 page/size |
| 场景法 | 登录 → 改密 → 请假 → 审批 → 返校 |
| 判定表 | 不同请假状态下允许的撤销、返校、续假操作 |
| 错误推测 | 重复提交、未登录、学生越权、非法 ID |
| 接口契约 | HTTP 状态、业务 code、字段类型和字符编码 |

## 4. 测试环境

| 项目 | 配置 |
| --- | --- |
| 操作系统 | Windows 10/11 |
| 浏览器 | Chromium（Playwright） |
| 前端 | Vue 3 + Vite，默认 5173 端口 |
| 后端 | Spring Boot 2.7 + JDK 8，默认 8080 端口 |
| 数据库 | MySQL 5.7/8.x，测试库 `student_leave_system` |

## 5. 准入与准出标准

准入：前后端可启动、数据库初始化完成、测试账号可用、主要接口无阻塞性 5xx。

准出：P0/P1 缺陷关闭，核心流程用例 100% 通过，其余用例通过率不低于 95%，自动化报告和缺陷记录完整。当前版本的 P0/P1 缺陷已经关闭并通过自动化回归。

## 6. 风险与优先级

1. 管理端涉及审批写操作，身份认证和角色授权为最高风险。
2. 首次登录强制改密会影响所有后续学生流程。
3. 初始化 SQL 重复执行可能污染回归数据，自动化尽量使用只读或非法参数用例。
4. 接口统一返回 HTTP 200，监控和调用方容易误判失败请求。

## 7. 自动化策略

- API 层优先覆盖稳定、执行快的认证、权限和边界场景。
- UI 层仅覆盖关键路径与前端独有校验，避免重复验证后端细节。
- 缺陷修复前使用 Playwright 预期失败标记保留证据；修复后移除标记并转为普通回归断言。
- 失败时自动保留截图、视频和 Trace，HTML 报告作为测试交付物。
